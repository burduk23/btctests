# История обновлений BTC Monitor Bot

## Версия 3.3.0 (2026-06-14)
**Оптимизация производительности и исправление логики уведомлений**
*Название коммита:* `performance-optimization-and-notification-fix`
- **Оптимизация производительности**: Внедрен параллельный опрос адресов через `asyncio.gather` с использованием `Semaphore` (лимит 5 одновременных запросов). Это значительно ускоряет цикл мониторинга при большом количестве адресов.
- **Исправление логики подтверждений**:
  - Устранена проблема "прыжков" через этапы подтверждения (например, пропуск уведомления о 1 подтверждении).
  - Бот теперь всегда получает актуальное состояние транзакции напрямую из API перед отправкой уведомления.
- **Исправление инициализации адресов**: Исправлен баг, из-за которого бот не уведомлял об уже активных транзакциях сразу после добавления нового адреса. Теперь первая проверка принудительно отправляет уведомления о текущем статусе.
- **Метки времени в уведомлениях**: В сообщения добавлена информация о времени первого появления транзакции в сети (`first_seen`).
- **Защита от Rate Limits**: Добавлена обработка ошибки HTTP 429 (Too Many Requests) с экспоненциальной задержкой, что повышает стабильность работы с публичными API.

## Версия 3.2.0 (2026-06-04)
**Исправление дублирования уведомлений и улучшение стабильности**
*Название коммита:* `fix-notification-spam-and-persistence`
- **Исправление дублирования**: Устранена проблема, при которой бот отправлял уведомления о старых транзакциях после каждого подтверждения.
- **Исправление сохранения (Persistence)**: Исправлен баг в `core/state.py`, из-за которого информация об уже отправленных уведомлениях не сохранялась в базе данных SQLite.
- **Совместимость ключей**: Улучшена логика проверки уведомлений для поддержки данных, перенесенных из старых версий бота (миграция ключей).
- **Стабильность мониторинга**: Оптимизирована функция `process_tx` для строгого соблюдения этапов уведомления: 0 подтверждений -> 1 подтверждение (если цель > 1) -> Целевое количество подтверждений.

## Версия 3.1.0 (2026-05-19)
**Исправление зацикливания уведомлений и оптимизация API**
*Название коммита:* `fix-notification-loop-and-api-optimization`
- **Исправление зацикливания**: Реализовано локальное хранение ID отправленных транзакций в файле `notified_txs.json`. Это предотвращает повторную отправку уведомлений после перезапуска бота.
- **Оптимизация API**:
  - Запросы к CoinGecko для получения цены BTC теперь выполняются не чаще одного раза в 5 минут.
  - Высота блока (tip height) теперь обновляется напрямую из WebSocket-сообщений mempool.space.
  - Опрос REST API (Blockstream) теперь выполняется только в случае падения WebSocket-соединения.
- **Документация**: Удалены разделы с планами на будущее из README.md.

## Версия 3.0.0 (2026-05-11)
**Переход на базу данных SQLite и переменные окружения (.env)**
*Название коммита:* `refactor-db-and-env`
- **Миграция на SQLite**: Все данные теперь хранятся в реляционной базе данных `data.db` вместо `state.json`. Это повышает надежность и производительность при большом количестве пользователей.
- **Автоматическая миграция**: При первом запуске бот автоматически переносит все данные из `state.json` в новую базу данных.
- **Поддержка .env**: Добавлена возможность настройки бота через переменные окружения. Файл `.env` теперь является рекомендуемым способом хранения токенов и настроек.
- **Обратная совместимость**: Бот продолжает поддерживать `config.json`, но значения из `.env` имеют приоритет.
- **Улучшенная архитектура**: Внедрена SQLAlchemy для работы с БД и Pydantic для валидации конфигурации.

## Версия 2.7.2 (2026-05-11)
**Поддержка MTProto прокси и глобальная настройка прокси**
*Название коммита:* `mtproto-proxy-and-global-proxy-fix`
- **MTProto Proxy**: Добавлена поддержка чтения настроек MTProto прокси из файла `MTProto.txt` (формат `ip:port:secret`).
- **Глобальный прокси**: Все фоновые HTTP-запросы (через `httpx`) и WebSocket-соединения (через `aiohttp`) теперь корректно используют настроенный SOCKS5 прокси.
- **Логирование**: Добавлены информационные сообщения и предупреждения при использовании MTProto прокси, так как библиотека `python-telegram-bot` требует HTTP/SOCKS5 бридж для работы с этим типом прокси.

*Название коммита:* `proxy-connectivity-fix`

## Версия 2.7.0 (2026-05-08)
**Поддержка SOCKS5 прокси**
*Название коммита:* `socks5-proxy-support`
- **SOCKS5 Proxy**: Добавлена возможность работы бота через SOCKS5 прокси.
- **Автоматическая настройка**: Бот автоматически считывает настройки прокси из файла `socks5.txt` (формат `ip:port:login:password`).

## Версия 2.6.0 (2026-05-03)
**WebSocket мониторинг и настройки подтверждений**
*Название коммита:* `websocket-monitoring-and-confirmations`
- **WebSocket API mempool.space**: Переход на WebSocket для мониторинга транзакций в реальном времени. Это значительно ускоряет получение уведомлений о новых транзакциях в мемпуле.
- **Отказоустойчивость (Fallback)**: Реализована система автоматического переключения на Blockstream REST API в случае сбоя или недоступности WebSocket-соединения.
- **Исправление уведомлений для админов**: Исправлен баг, из-за которого администраторы получали уведомления по всем кошелькам системы. Теперь уведомления приходят только по собственным адресам администратора.
- **Настройка подтверждений**: Добавлена возможность выбора количества подтверждений (1 или 2) для каждого адреса.
  - В Telegram боте выбор осуществляется через Inline-кнопки при добавлении адреса.
  - В Mini App добавлен выпадающий список в форме добавления адреса.
- **Обновление ядра**: Модель состояния и API обновлены для поддержки и хранения индивидуальных настроек подтверждений для каждого адреса.

- **Система рассылки**: Добавлена функция выборочной рассылки. Администратор может отметить конкретных пользователей в списке и отправить им текстовое сообщение.
- **Обратная связь**: Пользователи, получившие сообщение от администратора, видят кнопку «Ответить». При её нажатии они могут отправить текстовое сообщение, которое напрямую пересылается администратору (с указанием профиля отправителя).
